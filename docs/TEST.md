# 실기기 시험 체크리스트

KTX Driver 앱을 드라이버에게 배포하기 전에 실제 폰으로 확인할 항목이다. 한 번 시험할 때마다 이 표를 복사해 결과를 적는다.

| 기록 | |
|---|---|
| 날짜 / 시험자 | |
| 폰 모델 / Android 버전 | (예: Galaxy S25+ SM-S936W / Android 16) |
| 앱 버전 (`versionName`) | |
| 서버 | driver.withktx.com / test.ktxtransport.com |

결과 칸에는 ✅ 통과, ❌ 실패(메모에 증상), ➖ 해당 없음을 적는다.

## 0. 준비

- [ ] **release APK**로 시험한다(`ktx-driver-<버전>.apk`, [SIGNING.md](SIGNING.md) 5절). debug 빌드는 시험용 기능이 들어 있어 배포용 동작과 다르다.
- [ ] 폰에 debug 앱이 있으면 먼저 지운다(서명이 달라 덮어 설치가 안 됨. 지우면 로그인도 지워짐).
- [ ] 시험용 드라이버 전화번호와, 그 번호로 픽업할 시험 로드(Load#)를 준비한다.
- [ ] 서버(TMS) 작업이 끝났는지 확인한다. 끝나지 않은 항목은 ➖로 두고 나중에 다시 한다.
  - (S1) 픽업 완료 화면이 `KtxAndroidApp.startTracking(전화번호, "https://www.withktx.com/gps")`를 부른다
  - (S2) 배송 완료 화면이 실린 로드가 없으면 `KtxAndroidApp.stopTracking()`을 부른다
  - (S3) `/.well-known/assetlinks.json`이 driver.withktx.com과 www.withktx.com에서 리다이렉트 없이 200
  - (S4) `/app/version.json`과 APK 파일 호스팅
- PC에서 adb로 상태를 보려면 폰의 USB 디버깅을 켠다([SETUP.md](SETUP.md) 7절). adb 확인은 선택이다.

## 4. 위치 전송 (추적 중)

화면을 끈 채로 시험한다. 폰은 충전기에 꽂지 않은 상태가 실제와 가깝다.

| # | 할 일 | 기대 결과 | 결과 | 메모 |
|---|---|---|---|---|
| 4.1 | 화면을 끄고 **5분** 둔다 | 지도에 약 1분 간격으로 점이 계속 찍힌다 | | |
| 4.2 | 화면을 끈 채 **30분 이상** 운행(또는 대기) | 점이 끊기지 않는다. 카드가 회색(10분 무수신)으로 바뀌지 않는다 | | |
| 4.3 | **하트비트**: 추적 중 빠른 설정에서 "위치"를 끄고 7분 둔다 | 새 위치가 없어도 약 5분 뒤 마지막 위치가 한 번 더 서버에 도착(카드가 회색이 되지 않음). 위치를 다시 켜면 1분 간격 복귀 | | |
| 4.4 | **오프라인**: 비행기 모드 5분 → 해제 | 해제 후 1분 안에 비행기 모드 동안의 점들이 **순서대로** 도착(지도의 빈 구간이 채워짐) | | |
| 4.5 | 다른 앱(지도, 카카오톡 등)을 오래 쓰다 돌아옴 | 그동안에도 점이 찍혀 있다 | | |
| 4.6 | 8~10시간 근무 후 배터리 | 사용량을 메모(설정 → 배터리 → KTX Driver) | | |

## 8. 알려진 제약

- 앱을 **강제 중지**하면 Android 규칙상 다시 열 때까지 아무것도 실행되지 않는다(6.2).
- 재부팅 후에는 **잠금을 한 번 풀어야** 추적이 다시 시작된다(Android의 암호화된 저장소 규칙).
- 삼성 폰의 "절전 앱/사용하지 않는 앱 절전"에 KTX Driver가 들어가면 추적이 멈출 수 있다. 4절에서 끊김이 보이면
  설정 → 배터리 → 백그라운드 사용 제한에서 KTX Driver가 "절전 안 함"인지 확인한다.
- Google Play 밖의 앱이라 업데이트는 완전 자동이 아니다. Android 확인 화면에서 드라이버가 한 번 눌러야 한다
  (Android 12+에서는 첫 앱 내 업데이트 뒤부터 생략될 수 있음).
